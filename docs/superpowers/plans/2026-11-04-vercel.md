# URLScan Vercel Implementation Plan

> For agentic workers: use superpowers:executing-plans inline and one final independent review.

Goal: publish a real Python URL inspection workbench on an independent Vercel URL.
Architecture: retain local v2; add a stateless FastAPI cloud adapter and public-target transport; adapt the existing UI to cloud modes and browser history.
Tech Stack: Python 3.12, FastAPI, httpx/httpcore, plain HTML/CSS/JS, Vercel Functions.
Spec: docs/superpowers/specs/2026-11-04-vercel.md

## Global Constraints
- Public URLs on ports 80/443 only; validate and pin DNS for every connection and redirect.
- At most five URLs, two concurrent checks, five redirects, 512 KiB page body and 20 s per check.
- Sample and live provenance stay visible. HTTP posture is not a malware verdict.
- No SQLite writes or persistent background worker in the deployed app.
- New project only; no secrets or settings from unrelated projects.

## Review Focus
- DNS rebinding, mixed public/private DNS results, redirects and nonstandard ports.
- Timeouts, redirect loops, partial batch failure and oversized bodies.
- User-controlled HTML, headers and URLs rendered as text and exported safely.
- Honest UI counters, inspected navigation versus merely referenced resources, and provenance.
- Serverless filesystem/runtime imports and deployed API/static routes.
