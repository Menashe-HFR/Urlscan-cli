# URLScan Studio on Vercel — design

Goal: deploy an independent public URLScan Studio URL where a visitor can run an actual website check and inspect results and actionable insights.

User-approved scope: upgrade URLScan, deploy on Vercel, supply its own URL, provide a test run that returns UI results. Existing Python/FastAPI implementation and dashboard are retained.

Approaches: (1) existing SQLite queue plus an always-on host: preserves local durability but conflicts with the requested stateless deployment; (2) add managed storage/queues on Vercel: appropriate for future browser scanning but requires additional credentials and services; (3) a stateless Python inspection endpoint plus browser-owned history: chosen for this release, providing real results without provisioning paid dependencies or third-party keys. This is an implementation judgment within the requested deployment scope.

The live endpoint validates and inspects up to five public HTTP(S) URLs, follows at most five redirects, bounds DNS/network/body/time resources, and returns status, navigation evidence, security headers, parsed page metadata, baseline checks and prioritized recommendations. It never executes page JavaScript or claims malware detection. Network connections use validated and pinned public IPs so DNS rebinding and redirect-to-private targets are rejected.

The sample test calls the same deployed API with explicitly synthetic fixtures. Every UI result retains its source. Failed and incomplete checks stay unknown. Browser history/export are available without a shared server database. The legacy local SQLite workflow and optional urlscan.io provider stay available in the repository.

Release: isolated urlscan-studio folder, new codex branch / PR in Urlscan-cli, separate Vercel project and vercel.app URL in the existing team. No purchased domain, secrets or production settings from unrelated projects. Deployment must be tested through UI → API → real public response. Vercel team access is currently denied and must be authorized by the owner before deployment.
